# AGENTS.md

1. Capture the current behaviour with meaningful tests.
2. Identify the structural problem that makes change difficult.
3. Make the smallest reshape that addresses it.
4. Verify behaviour after each step.
5. Keep the refactoring only if it reduces the effort of understanding the code.

GitOps source for a live single-node k3s homelab. Flux applies `main`; changes reach the cluster only through Git or the documented `make` targets.

## Rules

- Update documentation in the same change as behaviour. Each topic has one canonical page (map below); link, don't copy. Describe what is, not what was. A change under `v2/` or `devtools/codegraph/` updates that workstream's page in `docs/workstreams.md` too; `make check-docs` checks the registry's state, next gate and uncommitted work against Git, so a record that goes stale fails a check rather than waiting to be re-read.
- Validate before every commit: `make check` (CI also runs `make check-templates`; run it yourself before pinning a template or changing app types or `app-new`). For script, Makefile or layout changes also run `for f in host/*.sh tests/fixtures/*.sh; do bash -n "$f"; done` (`make test` runs every dry run that only plans).
- Commit to `main` after validation, push, `make flux-reconcile`, verify on the cluster (`make verify-platform`, `make app-status`), then record dated evidence in `docs/current-state.md`.
- Confirm with the user before hard-to-reverse live actions: deleting data (`make destroy-data`, namespaces, PVs), rotating real credentials, changing where backups go, or anything under `flux-system`. `make app-repo` and the console's **Start a new app** create a real public GitHub repository and package; name throwaway ones `swhurl-try-<n>`. Once a throwaway's instance is removed, delete its repository and package with the tokens in the gitignored `secrets/` (`github-cleanup.sops.yaml` for repositories, `github-packages.sops.yaml` for packages; decrypt with `SOPS_AGE_KEY_FILE=./age.agekey`, and check the token is not empty: `gh` falls back to its own login, which cannot delete). Any other repository is the user's to delete.
- New operator logic goes in the `tools/swhurl` package, calling external tools only through `Runner` and tested with `FakeRunner`, and a new command is one entry in `tools/swhurl/commands.py` ([contributing](docs/contributing.md#operator-tooling)); keep short glue and host scripts as bash.
- Narrow exception: the offline v2 model, compiler and preview comparator live in the separate Go module `v2/`, with Go-native tests and direct CLI invocation, outside the Python command catalogue. Its layers are checked: 0 the pure model, 1 one adapter per dependency, 2 the use cases in `v2/orchestration`, 3 the command. All v1 tooling rules remain unchanged; external-effect adapters require separate approval. Before designing a v2 change, read the operator's [design principles](docs/iteration-2-plan.md#design-principles); they govern contract design and iterative transition, not v1 compatibility. See [phase-1 contract and checks](docs/iteration-2-plan.md#2-phase-1-model-and-contract). v2 keeps decisions in a pure model and effects in adapters, and reaches Kubernetes through the API server, never `kubectl` ([development layers](docs/iteration-2-plan.md#4-development-layers-and-adapters)). Its design rules are checked as code: run `make check-v2` after changing anything in `v2/` and fix what it reports rather than a rule's baseline ([guardrails](docs/iteration-2-plan.md#guardrails)).
- Narrow exception: the backup image's Go tool lives in `images/backup/tool/`, its own Go module with its own dependencies (`filippo.io/age`, a pure-Go SQLite) so v2's stdlib-only rule stands; `go test ./...` in that module tests it, and CI runs it beside `make check-v2`. It replaces the image's Python jobs, and its contract is the archive and metadata the Python job already publishes ([the slice](docs/iteration-2-plan.md#the-backup-image-in-go-option-c-part-one-27-october-2026)).
- Narrow exception: the read-only code graph development aid lives in `devtools/codegraph/` (standard library only), reads Git through its own revision reader instead of `Runner`, and is not a `swhurl` command; `make check-codegraph` tests it. It never imports or runs the code it analyses. Apply its [primitives and contracts](docs/visual-change-tool.md#4-primitives-and-contracts) to every change.
- Never print Secret values. Compare by bytes or hashes (`make check-secrets`, `make verify-platform`). `age.agekey` stays out of Git.
- Scripted `kubectl` needs `export KUBECONFIG=$HOME/.kube/config`; the k3s wrapper otherwise reads `/etc/rancher/k3s/k3s.yaml`.

## Working with the operator (draft)

- **Explain concretely.** Lead with an example; show before and after for renames and moves; draw a flow for anything crossing systems; say what an offered next step produces ("draft files, nothing applied"). After a change the operator can see, end with a "Test it yourself" block.
- **Verify like a user.** Check every entry point (http and https, signed in and out), prove scripts stop on failure, and read release notes and propose an upgrade path before merging a major version.
- **End every turn that advances v2 with progress against its goals.** Name what moved this turn in the terms of [the goals table](docs/v2-status.md#progress-towards-the-goals) (phase or capability, the evidence, whether it changed anything live) and the next gate. The table stays the standing summary; the report says what this turn did to it.
- **Act without asking** on warnings and doc gaps within the current change, offline-only fixes, and the next step of an approved outline. Stop for the confirm-first list above, a real choice between options, or scope growth.
- **Hand off commands precisely.** Label each block "run with `!`" or "run in your own terminal" (`sudo`, interactive logins; `!` has no terminal). Say what you will check afterwards, and watch long waits in the background instead of asking to be prompted.
- **Skills:** `decision-brief` before recommending a costly or undecided approach, `new-component-checklist` when adding anything that runs, stores data or holds a credential, `phase-handoff` for multi-step work.
- **Keep a session lean.** One session per slice, started with `/slice`; send broad exploration to a subagent so greps and file dumps stay out of the conversation; read long documents by section; keep a repeated script in a file instead of re-pasting it. Every turn re-sends the whole transcript, so context that is no longer needed is paid for again on every later turn. Measure with `pi-context-cost`.

## Commands

- Do: `make flux-reconcile`, `make verify-platform`, `make app-*`, `make check-secrets`, `make clickstack-bootstrap`, `make clickstack-dashboards` (idempotent; also keeps the two platform webhooks), and the throwaway live tests (`live-test-lifecycle`, `live-test-reloader`, `live-test-app-template`, `live-test-restore-mongodb`). Push fixture changes before running live tests: they reconcile from Git.
- Don't: delete Flux units or namespaces as a reset (there is no teardown), or `kubectl apply` resources that Flux owns.
- `platform-certs-*`, `app-new`, `app-promote`, `app-scale`, `app-expose`, `app-team`, `app-alerts`, `app-calls`, `app-egress`, `app-events`, `app-offers`, `app-sync`, `team-add`, `team-edit`, `team-remove`, `team-channel`, `channel-add`, `channel-remove`, `platform-signing-keys`, `app-remove` and `console-image` only edit files: commit and push before reconciling. After changing `tools/`, `images/console/` or the lock file, Validate's deploy job deploys the console itself with a bot commit to `main` ([console](docs/console.md#deploy-a-new-console)): `git pull --rebase` before the next push; `make console-image` is the manual fallback. `make verify-platform` warns until the new image runs.
- `host-dns` and `host-heartbeat` install system units with `sudo`: the operator runs them in their own terminal. The units run scripts from this checkout, so only template changes need a reinstall.
- Root units in `clusters/home/flux-system/kustomizations.yaml` are not reconciled by Flux: apply changes with `make flux-bootstrap`.
- Flux controllers come from `make flux-install` (`FLUX_VERSION` in `tools/swhurl/flux.py`, patches in `clusters/home/flux-system/install`); never plain `flux install`, which drops the patches.

## Lessons not obvious from the code

- **The egress proxy's configuration is v2's** (`platform/egress/{allocation,configmap,networkpolicy}.json`); v1 no longer writes it and `make check-apps` keeps only the grants' format. Regenerate it by direct CLI invocation from `v2/`: `swhurl-v2 egress --snapshot … --profile testdata/profile.json --previous ../platform/egress/allocation.json`, then `swhurl-v2 proxy --allocation … --profile testdata/profile.json --out ../platform`; `make check-v2` (and so CI) renders the allocation, the proxy's objects and `platform/auth` from the working tree's records and fails on any difference, so a changed grant or new instance cannot be left un-rendered. A database instance's backup host is granted from the profile, never declared by the instance. Grants are **enforced**: an ungranted host gets 403 and logs `granted=-`, and the instance's policy admits only DNS, its proxy port and its callers, so a client that ignores the proxy fails rather than escaping unseen.
- **Flux substitution** consumes unescaped `${...}` in any manifest of a unit with `postBuild.substituteFrom`; escape literal references there as `$${...}` (`make check-repo` fails on an unresolved one). Units without substitution, such as `platform-otel` with its `${env:...}` collector references, need no escaping.
- **Double base64** has caused one outage: `data` values are encoded exactly once; prefer `stringData`.
- **Traefik 3 (k3s chart 38)** ignores `ports.web.redirectTo`; the redirect is `ports.web.redirections.entryPoint`. The chart renders the redirect target as `:443`.
- **oauth2-proxy ForwardAuth** needs `upstream=static://202`, `skip-provider-button=true` and the middleware pointing at `http://oauth2-proxy-shared.ingress.svc.cluster.local/` (not `/oauth2/auth`) so unauthenticated browsers get a followable 302. `set-xauthrequest: true` makes it return `X-Auth-Request-Email`, which the console needs (a test with a hand-set header cannot show it is missing; only a real signed-in request can). `email_domains = []` must stay in `config.configFile` or the chart's `*` default admits any Google account. Switching to GitHub: `provider: github`, drop `oidc-issuer-url`, keep the callback URL.
- **Moving resources between Flux units:** never change the old unit's path in the same commit as the cutover; the old unit must be `Orphan` or suspended.
- **`flux reconcile` does not preempt** an in-flight `wait: true` reconciliation; new requests queue until its health checks finish or time out, and `lastAttemptedRevision` can look stale meanwhile.
- **A CronJob can stop scheduling when Helm updates it** as one of its jobs is being created (the controller logs `error syncing CronJobController` and does not requeue it). After a console deploy, check a checker job runs on the new image; the fix is in [troubleshooting](docs/operations.md#troubleshooting).
- **Deleting an app mid-install** waits for the Helm action timeout (3 minutes for app instances) before the finalizer releases the namespace.
- **ClickStack:** `hyperdx.config` changes do not restart the app (no checksum; Reloader does not watch `observability`): bump the `platform.swhurl.com/config-revision` pod annotation with them. Cold image pulls can exceed Helm's default wait (the HelmRelease sets `spec.timeout`). HyperDX registration stays open until a team exists and the team's ingestion key is random: `make clickstack-bootstrap` sets both from SOPS; the UI can rotate the key away from Git. Chart 3.x ignores `hyperdx.frontendUrl` (use `hyperdx.config.FRONTEND_URL`). ClickHouse renames a system log table to `<name>_N` when its definition changes. On ClickHouse 25.7 `system.query_log` has no `query_parameters`: match `query_id` against `clickstack-app` logs; `BAD_QUERY_PARAMETER (457)` with `nan` shows there as `param_HYPERDX_PARAM_*=nan`.
- **ClickHouse load** swings about 3x from hour to hour (merge time cycles over 3 to 4 hours), and cutting rows does not cut merge CPU: judge a change over a day against a baseline, not one window.
- **systemd unit templates** (`host/templates/systemd/`): `Exec*=` lines expand `$` and `%` themselves; write `$$` and `%%` for the shell. A `+` prefix runs that line as root despite `User=`.
- **Route 53** returns a wildcard record's name as `\052.homelab.swhurl.com.`; compare after mapping `\052` to `*`.
- **NetworkPolicy and HTTP-01:** cert-manager runs its challenge solver pods in the Ingress's namespace (port 8089); a policy selecting every pod there (`podSelector: {}`) blocks issuance with a 502. Select the workload's pods only (`make check-apps` rule `network-policy`). A pod can always reach itself, so test a policy from a different pod.
- **Calls between apps:** the k3s API server refuses anonymous requests (401 even with RBAC for `system:unauthenticated`), so apps cannot fetch the token-signing keys: they live in `apps/signing-keys.json` and reach apps as `SWHURL_AUTH_KEYS`. A projected service-account token without an `audience` is a real API credential: rule `call-tokens` allows only audience-bound ones. `SWHURL_ENV` must come before any variable using `$(SWHURL_ENV)`. The truth is `calls` on the caller and `allows` on the callee in `instance.yaml`; variables, tokens and NetworkPolicy are rendered (`make app-sync`).
- **The Java NATS client reads `$JS.API.STREAM.INFO.<stream>` before binding to a consumer**; the JavaScript one does not. A subscriber's NATS user allows it. A permission a client needs shows only as `Permissions Violation` in the app's log: try a new stack's subscriber live.
- **Events (NATS):** `platform/nats/users.yaml` is generated from the instances (`make app-sync`); never edit it. A changed user list reaches the server only when the kubelet refreshes the mounted config (one to two minutes), so a new app is refused at first and must retry. Helm replaces lists: everything in `authorization.users` must come from that one file. Stream and consumer names cannot contain dots: `<env>-<app>` and `<subscriber>_<event>`. `make app-repo` renders a new app from the template revision pinned in `STACK_REVISIONS`: pin a new template commit before creating an app that needs it. The offline check runs without `ruamel`, so `policy.py` must not import `edit.py` or `derive.py`.
- **What an app offers** (`apps/<app>/<env>/offers/`) is written by `make app-offers` and the Deploy workflow, never by hand; the workflow pushes to `main` with `GITHUB_TOKEN`, so its commits start no other workflow and it checks the app policy itself. The auto-merge gate lets a promotion carry the documents but holds one that changes what the app publishes.
- **App validation uses the records, not cross-environment manifest drift.** `model/store.py` checks that an app's Release records agree on kind and command; `model/generated.py` checks that manifests are exactly what their records render. Settings belong to each environment; a later promotion takes staging's Release, not its Settings. Test a new release with a production instance present.
- **Any commit to `main` leaves every unit a revision behind** until Flux has reconciled it (seconds), and every instance "Updating". Only the promotion gate asks whether the commit touched the instance's own files ([apps](docs/apps.md#a-commit-elsewhere-does-not-hold-a-promotion)); a new reader of `InstanceStatus.at_newest` that should not trip on other apps' commits wants `current` after `promotion.settled`.
- **logback's `JsonEncoder`** writes the message template and its arguments apart: `log.info("x {}", y)` reaches ClickStack as `x {}`. Build the string in the call.
- **A local `console --dev` left running serves old Python with new templates** (templates are read from disk on each request), which looks like a bug in the new code. `uv run` starts a child that outlives the wrapper's PID: stop it by its listening port and check nothing listens before trusting a page.
- **`pkill -f <pattern>` matches the shell running it** when the pattern also appears elsewhere on that command line, and kills the whole step. Stop a local server by its PID (`$!` in a script) or its listening port.
- **zsh does not split `$VAR` into words:** a command kept in a variable fails with "no such file"; put multi-step live checks in a `bash` script.
- **Checking from inside an app pod:** `kubectl exec ... node -e` (or a second JVM) starts another runtime in the app's container and can take it over its memory limit, restarting the app. Use `kubectl debug <pod> --profile=restricted --image=docker.io/curlimages/curl:<version>`: it shares the pod's network and namespace (so NetworkPolicy applies as to the app) but not its container's limit or env.
- **OTel node metrics** on k3s use host networking and the kubelet at `127.0.0.1:10250`.
- **Reloader** only acts in namespaces listed in its HelmRelease; add the namespace before opting a workload in (`make app-new --secret-keys` does).
- **`nginx-unprivileged`** listens on IPv4 only with a read-only root; use `127.0.0.1` inside the pod.
- **Managed label domain** is `platform.swhurl.com/*`; throwaway test namespaces carry `platform.swhurl.com/<test>=true` and scripts refuse to touch namespaces without it.
- **Stack templates** (`swhurl-app-template-*`, Copier): Renovate cannot see versions inside `*.jinja` files, so keep versions in plain files (the Kotlin `build.gradle.kts` reads answers from `gradle.properties` instead). The templates accept only the app types' answers (`APP_TYPES`): a new or changed type is a line in `APP_TYPES`, in each template's last-question validator and in its Template workflow matrix, and a changed type keeps its old answers in the validator until no app records them. Docker mounts `--tmpfs /tmp` noexec, unlike podman: anything that unpacks and loads a native library from `/tmp` (the SQLite JDBC driver) passes locally and fails in CI.
- `showboat` is not installed globally; use `uvx showboat ...`.
