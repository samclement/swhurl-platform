# Glossary

The words this repository uses for its own concepts, one meaning each. Code, commands, the console and the docs use them as defined here; each entry links to the page that explains the thing itself.

| Term | Meaning | Avoid |
| --- | --- | --- |
| **App** | What a team deploys: one repository, one image, one name (`demo-orders`). The name is a DNS label of at most 40 characters ([apps](docs/apps.md)). | service (kept for what the platform provides), project |
| **Environment** | Where an app runs: `staging` or `prod`. In code, `env`. | stage, tier |
| **Instance** | One app in one environment (`demo-orders/staging`). Everything about it is named from that pair: the namespace `<app>-<env>`, the Flux unit `app-<app>-<env>` in `clusters/home/app-<app>-<env>.yaml`, and its manifests in `apps/<app>/<env>/`. [`instance.py`](tools/swhurl/apps/instance.py) is the one place that says so ([apps](docs/apps.md)). | deployment, release, target |
| **Unit** | One Flux `Kustomization` in `flux-system`: what Flux applies and reports on as a whole. An instance has exactly one; the platform's own are listed in [architecture](docs/architecture.md#flux-units). | layer, component |
| **Per-environment setting** | A setting or file that staging and production may differ in; everything else must be the same in both (rule `env-drift`). [`per_environment.py`](tools/swhurl/apps/per_environment.py) lists each with where its value comes from and what a promotion does with it ([app policy](docs/apps.md#the-app-policy)). | override, VARIES |
| **State** | An instance's one live verdict: Healthy, Updating, Failing, Suspended, Stopped or Unknown, with the reason. [`state.py`](tools/swhurl/apps/state.py) judges it from the facts read off the cluster, for the console, `make app-status` and the promotion gate ([console](docs/console.md#use-it)). | status (kept for the facts), health (kept for what the notification checker decides to tell someone) |
| **Notice** | One message for a person: a title, a message, normal or high priority and a link. The checker, the notify service and the host heartbeat all build one and hand it to a sender; [`notice.py`](tools/swhurl/notifications/notice.py) is the one place that says how it is written for ntfy and for the notify service ([services](docs/services.md#notification-expectations)). | notification (kept for what arrives on a phone), alert (a ClickStack or Flux rule that fires) |
| **Command** | One thing an operator runs, `make <target>`: its name, the make variables it takes, its help line, whether it takes `DRY_RUN=true` and what it touches. [`commands.py`](tools/swhurl/commands.py) states each once ([commands](docs/commands.md)). | task, script |
| **Check**, **verify**, **live test** | In a command's name: `check` and `check-*` never touch the cluster, `verify-*` only read it, `live-test-*` act on it with resources they remove. In the code, a *live check* is one entry of `make verify-platform` and `check-repo` *validates* the files in Git. | validate (as a command name), test (for a live check) |
| **Declaration** | An app's `swhurl.yaml`, in its own repository: its **identity**, its **needs** and its **offers**. A grant field there is refused, naming the command that sets it. Each field is one of those kinds, and is either read once (when `app-new` creates the staging instance; afterwards the instance is the truth) or read again (`version`, `stack`, `provides`, `flags`, and the needs `port`, `healthPath`, `uid`, `telemetry` and `resources`, with every new staging image). [`declaration.py`](tools/swhurl/apps/declaration.py) is its one reader and says each field's kind ([apps](docs/apps.md#swhurlyaml)). | manifest (kept for Kubernetes files), app config |
| **Identity** (of an app) | What the app is: `version`, `stack` and `kind` in its `swhurl.yaml` (its name is the repository's). A change in the app's repository does not change the instance. Who a request comes from (a signed-in person or a calling app) is a request's identity, not an app's. | |
| **Need** | What an app's image needs to run, declared in its `swhurl.yaml` beside the code that needs it: `port`, `healthPath`, `uid`, `telemetry`, `resources` (the image's minimum), `database`, `databaseSize` and `secrets` (names only). | requirement, capability (for a single field) |
| **Offer** | What an app gives other apps, declared in its `swhurl.yaml` and read with each image: its API description and events (`provides`, `events.publish`) and its feature flags (`flags`) ([what an app offers](docs/apps.md#what-an-app-offers)). | provides (except as the field's name), contract |
| **Grant** | What the platform allows an app: its team, who can reach it (`exposure`), its alerts, the apps it may call and the events it may receive. It lives only in this repository and changes through a `make app-*` command or the console, so a push to the app's repository cannot widen it. | permission, declaration |
