# Contributing

How to change this repo without breaking the cluster or the docs. Commits go straight to `main`; CI ([`.github/workflows/validate.yml`](../.github/workflows/validate.yml)) is the gate, and Flux applies `main`.

## Agent-assisted changes

Use the [software change workflow](software-change-workflow.md) to agree an outcome, observable contracts, design boundaries, authority and evidence with a coding agent. It includes an operator quick start, a reusable task-record template and an illustrative promotion-preview proposal. Invoke it explicitly in your request; it is a procedure, not an installed command or permission to commit or deploy.

## Validation

Run before every push:

```bash
make check
```

`check` runs `check-repo` (`swhurl-v2 check-repo` decides relative Markdown links, the two tables the docs keep in step with Git, the names v2's compiled tree gives apps, SOPS structure, required Secret files and settings, and the active render paths; `v2/check-repo.sh` renders each path, substitutes it as Flux does and checks shell syntax; `SCHEMA=1` adds Kubernetes and Flux schema validation with `flux-schema`, which CI does not run; needs Go; never contacts the cluster), `test` (the unit tests in `tests/`), `check-apps` (zero-argument Go render equality and actual chart-output policy over every `v2-records` instance including production; team/channel validation uses the same whole-tree compiler path; needs Go and Helm, with explicit Go chart acquisition into the local cache; no Python on this target's path; [ownership](apps.md#the-app-policy)), `check-otel` (`platform/otel/check.sh`: renders each collector's HelmRelease with `helm template` and validates the rendered config, unmodified, in the image the render names, then runs the log fixtures through its processors in that image; only the pod's environment is stubbed; podman locally, `CONTAINER_RUNTIME=docker` in CI; no Python), `check-lint` (Ruff and ShellCheck at the versions CI pins) and `check-docs` (compares the [workstream registry](workstreams.md) with Git and checks each progress page's shape and size, so it is overwritten rather than appended to; `swhurl-v2 workstreams`, needs Go). `make check` runs them in parallel and keeps each one's output together. It leaves out `check-templates` (`v2/check-templates.sh`: every app type's rendered app through `swhurl-v2 names`, `swhurl-v2 image-declaration` and `swhurl-v2 declaration`; reads the templates from GitHub), which needs the network and runs in CI on every push: run it locally when a change touches a template pin or the app types (`v2/contract/stacks.json`), the names catalogue (`v2/contract/names.json`) or what the producer writes, so a refusal shows before the push (it builds `swhurl-v2` from `v2/` when `SWHURL_V2` names none, and CI sets `SWHURL_V2` to its own build). GitHub Actions runs the rendering and fixture checks in parallel jobs, alongside the operator tests, lint and dry runs. For a pull request whose complete diff only changes `apps/<app>/...`, `clusters/home/app-*.yaml` and/or the unit list `clusters/home/kustomization.yaml` (so a new app and a first promotion qualify), CI skips the template and OTel checks and the tooling job; none of the three reads the unit list, which `check-repo` builds. App policy and manifest rendering still run. A mixed, empty or unclassifiable diff runs the full workflow, as do pushes to `main`. A pull request or push that changes only apps' input records (`app.yaml`, `release.yaml`, `instance.yaml`, `offers/`, encrypted files; `tools/ci_changes.py`) is rendered with `make -s v2-render` in the workspace before `check-repo` and `check-apps`, so it is checked as `main` will hold it once the [Render workflow](../.github/workflows/render.yml) has rendered it; any other change is checked as committed, so a commit that leaves rendered files stale still fails. The offline collector fixture allows up to 30 seconds for startup and processing under parallel load, stopping as soon as its records flush. The template job caches Copier's `uvx` environment. Template sources are shallow-cloned once per stack during each check. Only Copier, run through `uvx`, is Python on the template check's path; the stack and name catalogues are v2's JSON files, which the Python tooling also reads.

The [producer contract](iteration-2-plan.md#producer-first-python-retirement-approved-5-november-2026)
has frozen Python-produced full-label goldens under `v2/adapters/appsource/testdata/producer.json`.
Do not regenerate them from the Go implementation: flags bytes affect release identity, so compare the
whole line, not just decoded JSON. The adapter's CRLF events fixture is marked `-text` in
`.gitattributes` so Git preserves its exact bytes. `producer` owns source rules/encoding, `adapters/appsource` owns
explicitly named file/YAML reads (including the original symlink behavior), and the real/fake reader
share a contract suite. The parser
exception is exactly that adapter, Helm and `adapters/manifests` (the checkout's Kubernetes YAML, for `check-repo`); no new dependency is needed. Run `make v2-deps` once before
offline binary builds; Validate already bootstraps its template job's binary dependencies.

Run `make v2-deps` once after checkout or a v2 dependency pin change, before offline builds/checks; CI and the console image build do so explicitly ([build contract](iteration-2-plan.md#offline-cli-and-build)).

Prerequisites (CI pins the same): `kubectl`, `helm`, `uv`, `jq`, Go 1.26 for `check-v2`, `check-apps`, `check-repo` and `check-docs` (the version `v2/go.mod` states), and Python 3 with the `check` dependency group from [`pyproject.toml`](../pyproject.toml) (PyYAML). `make test` runs in the environment `uv` builds from `uv.lock` (the `check` and `console` groups); after changing a group, run `uv lock` and commit `uv.lock`. `make console-dev` builds and runs v2's Go console.

`make check-repo SCHEMA=1` also needs `flux-schema`, which no CI job installs or runs ([why](iteration-2-plan.md#17-check-repo-in-go-the-decisions-not-the-subprocesses-approved-8-november-2026)):

```bash
go install github.com/fluxcd/flux-schema/cmd/flux-schema@v0.9.0
export PATH="$(go env GOPATH)/bin:$PATH"
```

CI also runs every `DRY_RUN=true` target and `REQUIRE_HELM=1` so Helm-based tests cannot silently skip. `make check-secrets` needs the age key, so it runs locally only.

## Operator tooling

**Bounded Go exception:** the offline v2 model, compiler and preview comparator are a separate module in [`v2/`](../v2/go.mod), with Go-native tests and direct CLI invocation, outside the Python command catalogue. External-effect adapters need separate approval; v1 retains all rules below. The [phase-1 contract and build instructions](iteration-2-plan.md#2-phase-1-model-and-contract) are canonical. `make check` does not run Go checks: run `make check-v2` (format, vet, tests and v2's [design guardrails](iteration-2-plan.md#guardrails)) as well as the applicable v1 checks. CI runs it in the tooling job, with Go set up from `v2/go.mod`, the chart v2's profile pins fetched first and `REQUIRE_HELM=1`, so its manifest check cannot skip.

**Code graph exception:** the read-only [code graph](visual-change-tool.md) development aid is a separate standard-library package in [`devtools/codegraph/`](../devtools/codegraph), outside `tools/` so it is not in the console image. It reads Git through its own revision reader instead of `Runner`, is not a `swhurl` command, and never imports or runs the code it analyses. `make check-codegraph` runs its tests (part of `make check` and CI); `make check-lint` lints it. Its [primitives and contracts](visual-change-tool.md#4-primitives-and-contracts) are canonical.

All v1 operator logic lives in the Python package [`tools/swhurl/`](../tools/swhurl), run as `python3 -m swhurl <command>` with `tools/` on `PYTHONPATH`; the Makefile's `$(SWHURL)` does that. A command that edits apps or needs the other locked dependencies is marked `uv=True` in [`swhurl/commands.py`](../tools/swhurl/commands.py) and `make` runs it through `uv run --frozen`; `make` stays the operator interface. Choose the language by what the code does:

- **Python** for anything that parses JSON or YAML or edits structured files, makes a safety decision or refusal, handles or compares Secret values, polls or cleans up after failure, or produces a pass/fail verdict.
- **Bash** for short linear glue (the commands that are one or two `kubectl` or `flux` calls: `app-logs` and `app-reconcile` run [`host/ops.sh`](../host/ops.sh), which checks its names before any call and is tested through `make` with fake executables), a streaming pipe nothing inspects, code that runs where Python dependencies are not guaranteed (the host timer installer, [`host/install-timer.sh`](../host/install-timer.sh), and its systemd unit templates), and command lists that double as documentation. `make suspend` and `make resume` instead call `swhurl-v2 unit --target` ([lifecycle](operations.md#lifecycle)). Kept bash uses `set -Eeuo pipefail`, has a dry-run path where it changes anything, and passes `make check-lint`; when it grows real logic, the logic moves to `swhurl` and the script calls it.

- Call external tools only through `swhurl.run.Runner`. It handles `DRY_RUN` (pass `mutating=True` for changes), redacts registered Secret values from every message, and can hide a command's output from errors (`secret_output=True`). Read output live, line by line and redacted, with `Runner.stream(args)` (closing it stops the command). Stream sensitive data with `Runner.pipe(producer, consumer)`: the processes share an OS pipe Python never reads, and either side failing raises (like `pipefail`). Pass credentials on stdin (`input=`), never in argv; backups give `mongodump` its login as a config file on stdin.
- Report through `swhurl.report.Report` (`[OK]`/`[BAD]`/`[WARN]` and the exit code).
- A reader that asks many independent things (a console page) wraps its runner in `swhurl.run.SharedReads`: inside `once()` an identical `kubectl get` runs once, and `runner.together(...)` runs independent reads at once (a plain `Runner` runs them one after another, so a command in a terminal is unchanged). At most three run at a time (`READ_SLOTS`): each is a `kubectl` process of about 56 MB, and the console's pod has 256 Mi. Nothing is kept from one page to the next, and only `kubectl get` is shared.
- Operator tooling runs external tools through `Runner` ([operator tooling](#operator-tooling)); v2 reaches Kubernetes through the API server, never `kubectl` ([development layers](iteration-2-plan.md#4-development-layers-and-adapters)). The console was the one long-running reader that used `kube.runner()`, and it is Go now, so nothing serves `kubectl` output from inside a pod.
- Unit-test with `swhurl.run.FakeRunner`: it records calls and answers from argv-prefix rules, and fails on any unexpected command.
- A new command is a function `(argv) -> int` with one entry in [`swhurl/commands.py`](../tools/swhurl/commands.py): its name, the make variables that become its arguments, its help line, what it touches (`LOCAL`, `GIT`, `READ`, `CLUSTER`, `THROWAWAY`, `GITHUB`, `HOST`), whether it needs `uv` and what `DRY_RUN=true` does (`PLAN`: prints a plan and touches nothing, which `make test` then proves; `READS`: reads without changing). Add its name to `COMMANDS` in the Makefile and a row to [commands](commands.md); `make help`, the usage line for a missing variable and `python3 -m swhurl`'s list follow from the entry, and `tests/test_commands.py` fails when the Makefile or the row differs. A name starting `check` must be `LOCAL` and one starting `verify-` must be `READ`. A `CommandError` a command does not handle is printed as one `[ERROR]` line by the dispatch.
- Words: app, environment, instance and unit are defined in the [glossary](../GLOSSARY.md); a container's settings are **variables**; the app another app calls is its **callee**; "service" is kept for what the platform provides, in the console too: one **Deployments** list serves the person using an app, the developer connecting to it and the operator (the app page's Use, Connect and Operate parts). Commands are verbs (`set_calls`) and policy rules are `check_*`.
- Layout: `run.py` and `report.py` (foundation); `commands.py` (every command, stated once); `platform.py` (repository paths and Flux unit discovery); `kube.py` (how a Kubernetes object's Ready condition is read); `yamlio.py` (every YAML read and every generated file written: PyYAML's safe loader and dumper through libyaml, which made the verifier's tests about three times faster and rendering instances about eight); `charts.py` (chart acquisition for the ClickStack render test). Its image is [`images/console/Dockerfile`](../images/console/Dockerfile), built from the repository root (`podman build -f images/console/Dockerfile .`; `.dockerignore` admits only what it copies). On each push to `main`, [`validate.yml`](../.github/workflows/validate.yml)'s `console-image` job builds it alongside the checks and pushes it to `ghcr.io/samclement/swhurl-console`, tagged with the commit SHA and `src-<hash of its inputs>`, and skips the build when that hash is already published. The tag is computed once, by [`images/content-tag.sh`](../images/content-tag.sh) (`console` or `backup`), which the workflow's two image jobs and `make verify-platform` run; `make console-image` ([`images/pin-console.sh`](../images/pin-console.sh)) pins the image of that tag (`content-tag.sh console --committed`, which refuses uncommitted inputs). How Render, Deploy and Validate's console image pin push to `main` is [`host/push-main.sh`](../host/push-main.sh), tested against real Git in `tests/test_push_main.py`.
- Console pages: Jinja templates in `v2/cmd/swhurl-v2/console/templates` and one stylesheet, [`static/console.css`](../v2/cmd/swhurl-v2/console/static/console.css). Use its colour roles (`--ok`, `--attention`, `--critical`, `--accent`) and type sizes rather than new values, the `state` and `icon` macros in `_status.html` for a status or an icon, and `data-confirm="what will change"` on a form that stops or removes something. No CSS framework and no build step: htmx, the fonts and the icons are files in `static/`, listed with their licences in [`static/LICENSES.md`](../v2/cmd/swhurl-v2/console/static/LICENSES.md); pages load nothing from another host (tested). A page that only shows state joins `SELF_REFRESHING` in `server.py`.
- Tests import `swhurl` directly (`from swhurl import ROOT`); `make test` puts `tools/` on `PYTHONPATH` and runs [`tests/run.py`](../tests/run.py), one test per job across worker processes, or one whole class when it has `setUpClass` (or its module `setUpModule`) so that setup runs once (`-j N` sets the count, `-v` lists jobs, `-k PATTERN` or `make test K=PATTERN` runs only the classes whose dotted name contains it) and ends with the slowest classes, or, when something failed, the `make test K=<module>` command that re-runs just the modules that failed. To run one file: `PYTHONPATH=tools uv run --frozen python -m unittest tests.test_recovery`. `test_command_safety.py` is the only place that uses fake executables, for what only a real process shows; everything else uses `FakeRunner`.
- The Makefile holds one rule for every command with a function (`swhurl make <target>` builds the arguments) and recipes only for sequencing and the host timer script: no shell `if`/loops, `sed`, `grep` or `jq`. Use `make` functions (`$(if)`, `$(foreach)`) for plain sequencing and move anything else into `swhurl`.
- Operator commits require the full `make check`. A console pull request gets Validate, which takes its app-only path for an eligible diff (tooling tests read frozen fixtures and the other check inputs are unchanged), and a person merges it. See [review and merge](console.md#review-and-merge).

## Checklist for a change

- **Where it goes:** a shared capability gets its own directory and Flux unit in `clusters/home/infra.yaml` or `platform.yaml`, with explicit `dependsOn`, `deletionPolicy: Orphan`, substitution only if its manifests use `${...}`, and decryption only if its path holds `*.sops.yaml`; add its row to the [Flux units table](architecture.md#flux-units), which `make check-repo` compares with Git (`platform.units()` is the inventory code and tests read). Apps are created by `make app-repo` and the `swhurl-v2 create` line it prints ([start a new app](apps.md#start-a-new-app)).
- **Secrets:** beside the consumer, following the [Secret rules](operations.md#secrets); add a `.sops.yaml` rule for any new path.
- **Checks:** for a live invariant, write one pure function in [`v2/observe`](../v2/observe) over the evidence it needs, read that evidence in `orchestration/platform_scope.go`, and add the group to [the catalogue](../v2/observe/platform_catalogue.go) with a sentence saying what passing means; the [operations table](operations.md#check-health) is that catalogue (a Go test fails when they differ), table-tested beside the check and in `tests/` for anything checkable offline. Prefer declarative wiring over new feature switches (`SKIP_VERIFY` is the only one).
- **Live proof:** for behaviour that only shows on the cluster, add or run a throwaway test like `make live-test-lifecycle`, then record what you saw, with the date and commit, in [current state](current-state.md).
- **Charts:** pin `version:` in the HelmRelease and keep the file and its HelmRepository under `apps/`, `clusters/`, `infra/` or `platform/`, where [Renovate](operations.md#chart-updates) finds them.
- **Root units** in `clusters/home/flux-system/kustomizations.yaml` are not reconciled by Flux; run `make flux-bootstrap` after changing them.
- **App-template fixture:** `tests/fixtures/app-template/records/` holds the records of the two throwaway instances `live-test-app-template` deploys (team `smoke`; `smoke-worker` and `smoke-web`, both `prod`, on the demo apps' images by digest). The rest of `tests/fixtures/app-template/` is their render, committed because Flux reads Git: `make v2-render` writes it beside the platform's tree, and `make check-v2` fails while it differs from what its records render. Change the records and render; never edit a rendered file by hand.

## Diagrams

Diagrams are Mermaid blocks in the page they explain; GitHub renders them, so there is nothing to generate or commit besides the text. Keep external systems outside the cluster subgraph, label only the edges that carry meaning, and show `Let's Encrypt (ACME)` wherever cert-manager appears and the telemetry path (app → OTel collector → ClickStack) in the container view. To check a diagram locally: `npx -y @mermaid-js/mermaid-cli -i diagram.mmd -o diagram.svg`.

The [repository blueprint](repository-blueprint.html) is the one generated diagram: a self-contained page built from a JSON model by the `repository-blueprint` skill's `build_blueprint.py`. To change it, open the page, take the model from **Edit DSL** → **Download**, edit it and rebuild; evidence links are relative to `docs/`.
