Architecture review · read-only · HEAD fb553653 · 20 Oct 2026

The model is sound. Its edges are where the complexity is.

The core of the platform is strict records → pure render → exact comparison → all-or-nothing write, and that pipeline is good. Most of the incidental complexity comes from code that goes around it: readers that treat rendered files as the truth, shared files with more than one writer, relations whose consent rules differ by kind, and the console, CI and status logic each rebuilding the same rule in their own way.

Sources: four parallel read-only reviews (model, relations, workflows and console, platform), each claim cited to file:line, with the main claims re-checked against the code. Nothing in the repository was changed apart from adding this file.

01The model

An app has two authors: its team, through swhurl.yaml in the app's own repository, and the platform, through records in this repository. Everything that Flux applies is rendered from those records.

ConceptMeansSource of truthWritten by
DeclarationIdentity, needs and offers of an app's imageswhurl.yaml at the image's commitDeveloper
ReleaseImage, needs and offers taken from the declaration; grants nothingapps/<app>/<env>/release.yamlDeploy workflow, promote, app-offers
SettingsGrants (calls, allows, subscriptions, egress), choices (scale, exposure, host) and allocations (egress port, nkey, volume) in one recordinstance.yaml (class Settings)Operator, console, app-sync (allocations)
AppTeam and alerts, shared by both environmentsapps/<app>/app.yamlOperator
Offers documentsOpenAPI, AsyncAPI and flags copied from the image's commitoffers/Workflow only
WorldEvery instance's records in memory, the only input to renderingstore.worldRead from disk
Rendered filesManifests, the unit and shared files; must equal the render byte for byteOutput of render.instance and render.sharedThe write pipeline (and, today, other writers)
StateThe live verdict on an instancestate.verdict over cluster factsNever stored

Three things make this model work: the instance name pins every path (instance.py), rendering is pure, and generated.py fails any drift between the committed files and the render. The findings below are the places where code doesn't yet rely on those guarantees.

06Awkward elements

Ranked by how much complexity each one causes. Each gives the evidence, what it costs, and a clearer primitive or contract to replace it.

1
Grants · relations · event registry

Rendered files are read back as if they were the truth

Evidence
derive.callers_of/subscribers_of parse other apps' HelmReleases (derive.py:70-86). events.users_file and egress.proxy_file/ports rebuild the NATS users and the squid ports from HelmRelease variables, while model/events.users and model/egress.proxy build the same files from records. checks.py:151,178 and policy rules use the first set; generated uses the second.
Cost
Two generators for each shared file. Docstrings that describe a source the code no longer uses. A real gap: a caller still waiting for consent renders nothing, so remove cannot see it, and a later app with the same name that allows it reconnects the call silently (inferred from the code, not exercised).
Clearer
Queries over the World only: callers(world, i), subscribers(world, i), entry.release.image. Live checks compare against render.shared(world). Delete users_file, proxy_file, ports, grants and the derive readers.
2
Platform/app ownership

Shared platform files have several writers, and some of them can only add

Evidence
render.shared computes the units and the Reloader namespaces. sync.apply only adds to them, through new.register and new.watch_namespace. edit.unwatch_namespace removes with a regex, and generated._reloader parses with another regex. The paths are written out four times (sync.py:22, generated.py:22, edit.py:694,709). Routes are written by derive.sync, outside the model.
Cost
When a namespace stops needing Reloader, check-apps fails and app-sync cannot fix it. Each app change also edits up to four platform units, so "the platform owns X" really means "the platform owns the template; apps own its contents".
Clearer
One Shared output that plan writes whole: users, proxy, Reloader list, units registry and routes. Its contract: a shared file is a pure function of the World plus the platform inputs; one writer; the comparison is of text. In docs/architecture.md, mark these files as "generated from apps/".
3
Operator · lifecycle

Remove goes around the write pipeline, and variants are expressed as booleans

Evidence
edit.remove runs rmtree, then filters the registry by line, then edits Reloader with a regex, and only then renders (edit.py:670-719). Elsewhere the variants are booleans: prepare(adding), change_release(adding, keyed), apply(register), and set_alerts(changes, none, default) with a sum(...) != 1 check.
Cost
A RenderError after the deletion leaves a half-changed tree. Every new lifecycle step adds another flag.
Clearer
prepare(root, {Instance: Create(entry) | Update(fn) | Remove}). Removing an instance takes it out of the World and lets the render decide every deletion. The alert choice becomes a union type.
4
Grants · security keys

Settings holds three meanings, and allocation is scattered

Evidence
Grants, choices and allocations share one record (records.py:212-228). The NATS key is made in new.generate, change_release, set_events and nats_keys; the volume in take_release, new.records and first_production; the port in sync.allocate. Commands edit Entry.encrypted so that a file they write later will be counted. No command rotates an nkey.
Cost
Promotion has to know, field by field, what to copy (Release), what to keep (choices), what never to copy (grants) and what to make fresh (allocations). The auto-merge gate re-derives the same split.
Clearer
Split the record into Grants (operator-only, never promoted), Choices (per environment) and Allocations (machine-owned, a sibling of the other two). Add one allocate(world, platform) step inside prepare that makes missing keys and volumes and rolls them back on refusal. Rotating a key then means dropping the allocation and syncing (app-sync --rotate nkey).

Cost
Users have to learn three rule sets. The console needs a "waiting" state for calls only. remove blocks on subscribers but not on waiting callers. The calls policy rule checks again what generated already proves. The Consumer name {publisher}-{event} can collide: a-b.c and a.b-c both give a-b-c (events.py:201).

One Relation(kind, from, to, env) primitive with one table of consent rules and a single state set: pending | connected | refused. A missing target is pending for every kind. Rendering, the console's map, remove's guard and the docs all read that table. Name Consumers with a separator that cannot appear in names, or refuse a collision.
6
Operator · developer · promotions

"main is rendered from its records" is enforced by five writers

Evidence
The CLI writes records and rendered files. Console PRs keep records only, discarding the clone's render. The gate, Render and Deploy each render again and push with their own retry loop (3, 5, 5, 1 attempts). Deploy skips check-repo. The branch grammar is parsed in 4 places, and stages.BRANCH is looser than merge.BRANCH. The rule for encrypted files exists in both the console (changes.py:390-404) and the gate. Change.open picks its behaviour from kind and commands[0].name, and promotion goes around Change.
Cost
Each new console action needs edits in changes, merge, stages and server. git pull --rebase is needed before every push.
Clearer
An Action registry as the single source: Action(kind, envs, owns(path), commands(form), rule(main, changed) → reason | None, branch). The console labels a PR with rule, and the gate re-judges it with the same rule and the same inputs. Promotion, new app and remove become entries; remove's rule is "always held". One push_rendered(main) helper is used by every bot.
7
Promotions · console

About six status models and two meanings of "applied"

Evidence
InstanceStatus.applied means the revisions are equal (ops.py:147). stages treats a matching render hash as applied (stages.py:180), across 11 Rollout states. In between sit Target, Track, pull_progress strings and AppRow, joined inside the route layer (server.change_rows). source_problem runs up to six times for one console promotion.
Cost
The AGENTS.md lesson about current versus settled exists because of this. Each check costs kubectl reads and GitHub compare calls.
Clearer
One read model: Progress(git: Target, live: InstanceStatus) → State, where a matching render hash is the only proof of "applied". Judge the promotion precondition once per job and pass the result on. settled then serves only promotion.
8
API contracts · platform/app interface

No single list of what the platform gives an app

Evidence
SWHURL_* names live in calling.py:19-29 and events.py:47. Label keys are spread across contract.py, app_alerts.py, backup_job.py and recovery.py. Vocabularies are duplicated (KINDS, EXPOSURES, DATABASES, NAME_RE in 4 places). The S3 URI is in two constants. The host and cookie rules exist three times.
Cost
A rename breaks apps at runtime, not at validation. The templates in other repositories can only follow by convention.
Clearer
A standard-library contract.INTERFACE: one entry per variable or label, giving its name, who writes it, who reads it and its capability. A check keeps it equal to a table in docs/apps.md (as verify.table() does) and to the templates' helpers. Vocabularies are imported from records.py only.
9
Structure

Overloaded names, an awkward import constraint and oversized modules

Evidence
sync has 5 meanings, release 5, and instance 3 (value, folder, instance.yaml holding Settings). EditError lives in yaml_file.py, which imports ruamel; that is part of why policy.py must avoid edit and derive. edit.py is 1011 lines with five jobs, server.py 1077, changes.py 881.
Clearer
Move the error types to a standard-library apps/errors.py. Rename model/sync.py to model/write.py and dissolve derive.py. Split edit.py into cli.py (argparse), model/transitions.py (pure Entry → Entry) and operations.py. Split changes.py into github, proposal, forms and activity.
10
Platform operations · notifications

Five notification paths, and ClickStack state set outside Flux

Evidence
The senders are: the Flux Alert to ntfy, the checker (inside the console release) to ntfy and notify, the host heartbeat, and two imperatively created HyperDX webhooks. The ntfy topic is stored in 2 SOPS files plus HyperDX. The ingestion key and the webhooks are set by make targets. Two separate switches suspend backups.
Clearer
A behaviour decision, not a refactor (see options in section 08): route the Flux and ClickStack alerts through notify /v1/alert and keep the heartbeat direct to ntfy; then fold the ingestion key and webhooks into the dashboard reconcile CronJob.

07Clearer primitives

The target shape: the same pipeline, with every writer and reader going through it. Teal marks a new or reshaped primitive.

Sketch of the reshaped record and relation

Entry      = App, Release, Grants, Choices, Allocations, encrypted   # encrypted: a fact read from disk
Grants     = relations: [Relation], team-scoped allows, exceptions
Relation   = kind: call | event | host ; from: Instance ; to: App | team:<t> | host:port ; env
CONSENT    = { call: "callee allows", event: "open within env", host: "operator grant" }
state(r, world) -> pending | connected | refused          # one table drives render, console, remove
promote(staging, prod) = prod with Release := staging.Release   # Grants, Choices, Allocations never move

This split keeps instance.yaml as one file on disk; only the parsed shape changes. A different file layout would mean migrating every app's records, and nothing in this review needs that.

08Order of work

The steps are ordered by leverage per unit of risk. Steps 1 to 4 change no behaviour, and each one makes the next smaller.

  1. Fix the stated contractsdo first
    Reword AGENTS.md:64 and the calling.py/egress.py docstrings to name calls/allows as the truth. Point the policy.py:64 exceptions docstring at instance.yaml. Fix the calls fix hint. Add check-repo to deploy.yml:150. Add the missing platform-backup node to the architecture diagram. Hours, offline.
  2. Records-only readers (F1)
    Add queries(world); delete users_file, proxy_file, ports, grants and the derive readers. Closes the reconnect gap for waiting callers.
  3. One writer for Shared (F2), then remove as an operation (F3)
    Together they delete register, watch_namespace, unwatch_namespace, the line filter and the regexes.
  4. Mechanical structure (F9)
    Move the errors to the standard library, rename sync to write, split edit.py.
  5. Grants / Choices / Allocations and the allocate step (F4)
    Promotion and the gate then read one split instead of re-deriving it. Adds nkey rotation almost for free.
  6. Relation primitive (F5)
    Changes behaviour: a missing publisher becomes pending instead of a RenderError. Needs your call.
  7. Action registry and Progress read model (F6, F7)
    The largest change and the biggest payoff for the console. Start by moving the branch grammar and the encrypted-file rule into ACTIONS, and giving held the same staged input on both sides.
  8. Notifications and ClickStack (F10)
    A behaviour and trust decision; run decision-brief first.

09Evidence and gaps

Re-checked against the code

  • calling.py:4-8 and AGENTS.md:64 still describe the variables as the truth.
  • events.users_file, egress.proxy_file and ports sit alongside model/events.users and model/egress.proxy; checks.py:151,178 use the first set.
  • derive.callers_of and subscribers_of parse rendered HelmReleases.
  • edit.remove does rmtree, a line filter and a regex before rendering.
  • The Consumer is named f'{publisher}-{event}' (events.py:201).
  • stages.BRANCH is looser than merge.BRANCH.
  • deploy.yml runs only check-apps.
  • source_problem is called at 6 sites.
  • The Reloader and registry paths are duplicated in sync.py, generated.py and edit.py.

Not verified

  • The silent reconnect after remove is inferred from the code, not exercised.
  • Whether concurrent console PRs actually conflict on shared files.
  • Whether Renovate can bump files under apps/ that are rendered.
  • No tests or make targets were run; this was a read-only review.

Outside the design, but needs a decision

profiles/secrets.env exists. It is gitignored and nothing in the repository references it; the platform reviewer reports that it holds pre-SOPS plaintext credentials. Values were not printed. Deleting it and rotating any keys that are still live are confirm-first actions.
